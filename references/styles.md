# 解说风格卡

默认视觉仍是 references/design-system.md 的蓝图（深蓝底、琥珀强调、红只表示判定）。不要为了接近某支片子丢掉它。只有用户指定风格，或题材明显对不上蓝图时，才换下面的一张卡。换卡改的是这一条片子的配色、笔触和动作，不改 `templates/` 的行为。

风格卡记四件事：配色、笔触、动作怎么做、当前短板。记法来自花叔 2026-10-06 的文章（<https://x.com/AlchainHust/status/2107347834668224687>），仓库在 <https://github.com/alchaincyf/huashu-art-motion>。下面八张是按本仓库 1080×1440 画布写的用法，不是那个仓库的原文，也不要安装它。

艺术史穿梭只作可选参考，不是默认外观。文中列过的名字包括：洞穴壁画、古埃及、浮世绘、印象派，以及梵高、蒙克、达利、霍珀、波普、吉卜力、新海诚、蒸汽波。用户明确要求某一种时，仍用同一张卡的四格（配色、笔触、动作、短板）记下来，不要把它写成新的默认设计系统。

换风格之后，`templates/check.py` 第 4 项仍要求每帧 B>G>R。新配色若不是深蓝底，这一项会误报。交付前按新配色改这一项的判定，并在实践笔记里写明。不要为了让校验变绿把画面改回蓝图，也不要改 `check.py` 的其他项。

所有卡共用 design-system.md 的安全区：内容 y 150–1100，抬头 y<90，图签在右下，字幕 y 1290–1400。一屏一个信息点。

## 白板

- 何时用：口播长解说，跟着一句话把人物、事件和关系画出来。花叔文中认为这种白板适合 B 站和 YouTube 的长解说与教程。
- 配色 / 笔触：近白或浅灰底，墨色线，一个强调色。描边为主，少填色。
- 动作：用 `setDraw` 让线跟着口播长出来。摄像机缓推放轻，避免整张纸在晃。
- 短板：字一多就像幻灯片。持续运动用笔尖和线条延长，不要堆贴纸。

## Vox

- 何时用：同一份事实要新闻杂志感（地图、档案卡），而不是工程蓝图。花叔用白板和 Vox 讲过同一个 SpaceX 题目，换的是表达，不是事实清单。
- 配色 / 笔触：浅底、黑字、一块亮色。粗几何，少渐变。
- 动作：地图和卡片用位移入场。数字仍可计数，阴影改浅，少用屏震。
- 短板：亮底上再加琥珀会脏。强调色只留一个。红仍只表示判定。

## Kurzgesagt

- 何时用：抽象机制（尺度、系统、过程），需要扁平隐喻，不需要工程图签。
- 配色 / 笔触：高饱和色块，细描边或没有描边。
- 动作：整体平移和缩放（从小到大），缓动用 `eo`。少用屏震和扫描线。
- 短板：色数容易超过本仓库的五色纪律。超过就砍，不要为了「像」加光斑。

## 3Blue1Brown

- 何时用：数学、算法、模型结构。口播是梯度下降一类时优先这张，而不是白板涂鸦。花叔文中把 3Blue1Brown 和数学、AI 概念放在一起。
- 配色 / 笔触：深色底可以沿用 `#0E2843`。图形用一种亮色，坐标轴和公式是主体。
- 动作：绘制生长。向量和曲线按公式移动，变换要看得出前后关系。不要加装饰粒子。
- 短板：公式容易挤出安全区。一屏一条，字由代码排。

## 发布会 UI

- 何时用：软件步骤、界面操作。花叔文中把「发布会 UI」用于教程里的界面操作。
- 配色 / 笔触：中性灰界面，一个产品色。细边、小圆角、少阴影。
- 动作：光标先移到控件再点击，状态变化跟口播。点击可对一个 tick，每场景仍不超过两个重音（audio.md）。
- 短板：真实截图一多就不能改、也不能复现。能用 HTML 画的界面就用 HTML 画。

## 财经图表

- 何时用：对比、时间序列、一张图能说完的数据。数字只来自 `shots/facts.md`。花叔文中把财经图表用于讲数据。
- 配色 / 笔触：沿用蓝图底和琥珀强调即可，不必换系统。
- 动作：轴线先生长，柱或折线跟着数字长，标注引线先行（motion.md）。
- 短板：一屏多条曲线。一个场景一条结论。

## 故事

- 何时用：有人物、有因果关系，一张数据图讲不完。
- 配色 / 笔触：仍不超过五色。可以有一条很浅的场景色弧，角色外形整片不变（见 pipeline.md 的分镜习惯）。
- 动作：切镜头由动作带出（走进、落下、遮挡），不要硬切。表情用透明度或形变缓动，不要在两帧之间换一张脸。
- 短板：角色一复杂就想用生成式视频当底。按下面的角色规则做。

## 动态文字

- 何时用：句子本身就是画面，字少、概念短。
- 配色 / 笔触：大字加一种强调色。字号仍走三级制（design-system.md）。
- 动作：不超过六个字时用逐字 stagger。关键词变色的时刻对齐口播。
- 短板：句子长了就失败。超过六个大字就改成底部字幕，不要全屏堆字。

## 角色

不要让图像模型直接出视频。

- 有图像模型：它只画姿势静帧。代码只做位置、缩放和换帧，再用 SVG 或 CSS 滤镜叠上当前风格的笔触。图内无字，见 design-system.md 第五节。这是花叔文中的做法。
- 没有图像模型：用几何图形画角色，或用用户给的角色图。不要临时发明一张脸。

## 拆参考片：运动热力图

复刻或复查时，对相邻帧做差分，看哪些区域真的在动。花叔文中用一张运动热力图检查原片：每个时代大约只有一秒，但浪在卷、字在闪，画面内部一直有动作。冷区就是这一拍没有内部运动，回到 motion.md 的持续层补上。算法见 references/qa.md。热力图不代替数据宪法，也不要把它当成新的渲染引擎。
