# 代码视频：五步与确定性

本仓库的成片仍走 SKILL.md 的九步，画布仍是 1080×1440 的单文件 HTML。这一页只说明「视频是程序画出来的」，片子变长或要跟外部做法对齐时用，不替换九步。

来源：宝玉，2026-09-30，<https://x.com/dotey/status/2105181393638531536>。文中引用的官方发布：<https://www.anthropic.com/claude-opus-5-5>。文中作为长片分镜例子的拆解：<https://www.orcarouter.ai/blog/claude-opus-5-5-video-plan-one-shot>。

宝玉文中的结论是：那篇官方发布没有写视频能力，重点是写代码、操作电脑和知识工作。模型输出文字，不输出像素。本仓库不把模型当成视频模型。下面凡是「文中」都指这篇，数字没有在本仓库复核。

## 模型交出的是程序

要回答的只有一个问题：第 N 帧长什么样。随便给一个时间（文中的例子是第 2.5 秒），程序画出这一刻的完整画面。浏览器或渲染器逐帧画好，再拼成 MP4。

本仓库已经是这个形状：`templates/anim.html` 的 `setTime(t)` / `render(t, d)` 是纯函数，`shoot.py` 跳到该时间再截图，`render.py` 用 ffmpeg 编码合成。不要改成录屏。

## 五步

文中把流程拆成五步。规划、画面、动作是模型写的代码；声音、拍摄与合成是外部工具。配音有两个去处：给动作当时间表，也作为音轨交给 ffmpeg。

### 1. 规划：脚本和分镜

先写口播，再拆镜头。每个镜头写清画什么、持续多久、配什么话。本仓库对应 ① 数据宪法和 ② 文案：事实进 `shots/facts.md`，口播进 `shots/vo_lines.json`。60–150 秒的短解说不要再叠一份分镜文档。

分镜习惯只给明显更长的片子。文中的例子是 156.6 秒的 MV《I'm Upping My P(doom)》（项目名 PDoomVideo）：作者只指定一个角色，要求每句歌词有画面和转场，没有给具体场景。模型自己写了 STORYBOARD.md，规定：

- 角色设计整片固定
- 配色有一条弧（文中的例子：暖奶油 → 太空紫 → 警报红 → 回到起始）
- 每个镜头都有东西在动；那支 MV 的画面里不放文字
- 表情渐变，不突然跳
- 切镜头由动作带出（文中的例子：一口咬下去黑屏、一次坠落、镜头穿过一只眼睛）

然后按章节分文件：每一段时间轴一个 JavaScript 文件。文中写这支片子内部做了两轮。「一句话一次成型」指的是用户只发了一句，规划、分工和返工发生在模型内部。文中说源码公开，本仓库不转载，拆解以上面的链接为准。

**本仓库何时拆文件。** 默认不拆。一种视觉、一条 60–150 秒的解说，留在一个 `anim.html`，`setTime(t)` 仍是全片唯一入口。只有时长明显超过 150 秒，或分镜分成几章、每章一张不同的风格卡（见 styles.md）时，才按章拆成多个 HTML。每章仍是纯函数，时间原点对齐同一条总时间轴，最后 ffmpeg concat。不要把短片拆成一人一个文件。

「画面不放文字」是那支 MV 的规定。本仓库的解说片要字幕和标签，字由代码排（design-system.md），这条不要照搬。

### 2. 画面：用代码画

形状、颜色、角色由代码描述，不依赖现成素材库。本仓库默认 HTML + CSS + SVG。

下面只在题材需要时用，不替换骨架：

- 网页 3D：three.js，常写在一个 HTML 里
- 手绘感：p5.js 加笔刷库（文中那支 MV 的路线）
- 数学动画：Manim（Python）
- 要建模和贴图：把 Blender 当 Python 库写脚本

需要照片时，先让图像模型出静帧，再放进网页。图内无字。角色怎么放，见 styles.md。

### 3. 动作：锁在时间点上

第几秒、哪个东西、怎么动。文中的两种写法，效果相同：给定时间点，画面唯一。

- GSAP：时间轴可暂停，也可跳到任意时间。文中的两行是「第 2 秒星星从无到有弹出来，第 3 秒角色向右走 400 像素」。文中写开源工具 HyperFrames 默认用 GSAP。出处：<https://www.heygen.com/research/html-to-video>。
- Remotion：每一帧是帧号的函数，用帧号算位置、透明度和颜色。

本仓库是第二种的纯 JS 版本：`render(t, d)`。不要迁到 Remotion，也不要把骨架改成 GSAP。HyperFrames 和 Remotion 只是上下文。

HeyGen 在同一篇文章里的经验是：React 约束变多之后，agent 的产出更保守。这是他们的经验，不是普遍事实。不要据此改本仓库的 HTML。

持续运动、入场和转场的具体参数仍以 references/motion.md 为准。

### 4. 声音：配音是时钟

带旁白的片子先做配音，画面去对齐。字级时间戳、已有录音、以及「歌本身是时钟」，见 references/audio.md 第五节。不要换掉 `vo_tts.py`。

### 5. 拍摄与合成：跳到那一帧再拍

无头浏览器按时间跳帧截图，不是录屏。本仓库用 Playwright（`shoot.py` 里 `setTime` 然后 screenshot），ffmpeg 合成音画。并行截多段只有在下面的禁令成立时才安全。

## 确定性禁令

渲染过程中禁止：

1. 墙钟时间（`Date.now()`、`performance.now()` 驱动画面）
2. 未设种子的随机（`Math.random()`）。`music.py` 用 `default_rng(2026)`，种子固定，可以
3. 渲染期间联网。字体、图片、脚本必须在开拍前就在本地

内嵌视频必须先用 ffmpeg 拆成静帧，再按帧号贴上。不要在页面里放 `<video>` 让它自己播。

字体和 SVG 必须在开拍前就绪。这是 HeyGen 的发现（<https://www.heygen.com/research/html-to-video>）：没就绪就截，前几帧会缺字或丢图形。`shoot.py` 在打开页面后等了 400ms。本片若加了新字体或大 SVG，先确认加载完，再跑分段。

## 不要用代码视频当底子的时候

照片级的人脸和动物。生成式视频可以做插入，文中点名 Seedance、Kling、Runway Aleph。插入的是那几秒，不是整片的渲染器。插入段也要预先拆帧，遵守上面的禁令。

比较时看这些轴，不要只看「像不像照片」：文字准不准、能不能局部改、旁白能不能卡到帧、同一输入能不能再渲染出同一片，对面才是照片级真实感。

文中还写了限度：场景容易过曝；token 费用是真的。文中写 Opus 5.5 的 API 价格是输入每百万 token 4 美元、输出每百万 token 20 美元，并写一条约 3 分钟的旁白短片大约用掉一周 Claude 额度的 7%。这是该文的数字，不是本仓库核实过的价目。好不好看仍要人看，见 references/qa.md。
